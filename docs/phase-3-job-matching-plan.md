# 阶段三：岗位匹配与简历评分

## 阶段目标

把“简历画像”转成可解释、可追溯的岗位匹配结果。阶段三的结果必须绑定岗位、简历和画像版本，用户刷新页面或修改画像后，不能把旧版本的分数当成当前结论。

## 当前系统审计

| 范围 | 当前问题 | 阶段三处理 |
|---|---|---|
| 岗位候选集 | 匹配接口最多读取 20 个岗位，已有地区和方向筛选基础 | 保留第一版候选集上限，后续增加搜索、分页和排序 |
| AI 输出 | JSON 解析失败时生成随机分数，结果不可验证 | 严格解析和校验，失败返回可重试错误，不落库 |
| 版本一致性 | 结果只保存 `resume_id`，没有画像版本 | 保存 `resume_profile_version`，关联确认时的版本 |
| 可解释性 | 只有一段原因和建议 | 增加评分维度、证据和关键差距 |
| 前端状态 | 进度条是模拟进度；错误没有稳定展示 | 保留视觉进度，但增加明确成功、失败、无结果和未确认状态 |
| 数据安全 | 服务端已有用户身份校验 | 继续使用 Bearer token 和 RLS，禁止信任客户端 `user_id` |

## 第一版评分契约

AI 必须为每个候选岗位返回：

- `match_score`：0 到 100 的整数总分。
- `score_breakdown`：ATS 可解析性、关键词、经历、成果证据、地区策略、画像适配度六个 0 到 100 的整数维度。
- `match_reason`：基于简历和岗位要求的简短解释。
- `evidence`：来自简历或岗位要求的证据片段，最多 8 条。
- `key_gaps`：最关键的差距，最多 8 条。
- `suggestions`：后续简历优化建议。

服务端只接受合法岗位 ID、完整字段和合法数值范围。返回重复岗位、未知岗位、缺少岗位或非法字段都视为 AI 输出失败。

## 数据快照

`ai_matches` 保存一次匹配的结果快照：

```text
user_id
resume_id
resume_profile_version
job_id
match_score
score_breakdown
evidence
key_gaps
match_reason
suggestions
created_at
```

这份快照用于后续简历优化、收藏、投递和效果分析。画像被用户修改后，新匹配必须使用新版本，历史结果仍保留但不能冒充当前结果。

## 开发顺序

1. 增加 `ai_matches` 的画像版本和结构化评分字段。
2. 重写 `/api/ai/match` 的 AI 输出解析、校验和批量落库。
3. 前端只允许选择已确认画像，并展示失败原因、证据和关键差距。
4. 增加服务端契约测试和未登录、未确认、AI 输出无效、数据库失败测试。
5. 使用真实岗位和真实 Coze 配置完成浏览器验收。
6. 已补充用户收藏接口和岗位页收藏操作。
7. 已补充 `jobId` 目标岗位评分入口，后续接入岗位详情页的简历选择和评分展示。
8. 已完成岗位详情页的简历选择、目标岗位评分、评分快照读取、评分维度/证据/差距展示和收藏状态。

## 验收矩阵

| 场景 | 预期结果 |
|---|---|
| 未登录请求 | 401，不查询岗位，不调用 AI |
| 简历未确认 | 409，不调用 AI，不写匹配结果 |
| 没有候选岗位 | 返回空数组，不调用 AI |
| AI 返回非法 JSON | 502，不写随机或半成品结果 |
| AI 返回未知岗位或重复岗位 | 502，不写结果 |
| AI 返回合法结果 | 所有结果带当前 `resume_profile_version` 并批量保存 |
| 页面重复点击 | 请求期间按钮禁用，旧结果清空，失败可重试 |
| 画像版本更新后再次匹配 | 新结果使用新版本，旧快照不被覆盖 |

## 阶段三暂不包含

- 自动替用户投递岗位。
- 自动修改原始简历文件。
- 用模型分数替代最终招聘判断。
- 在 AI 不可用时伪造推荐结果。
